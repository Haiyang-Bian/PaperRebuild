# 开发与研究质量规范

本页是质量规则的权威来源，智能体入口与贡献指南引用本页。

## 软件开发

1. Julia 基线 1.12.6，依赖用 Pkg 管理并提交锁文件。
2. 增量实现小函数和模块；大规模重构先说明影响与迁移方式并取得授权。
3. 导入模块不启动实验、网络访问或文件写入；副作用放在明确脚本入口。
4. 参数、路径和种子显式传入；错误不得悄悄变为零值或成功状态。
5. UTF-8、LF、Julia 四空格缩进、JuliaFormatter default 样式及 100 字符行宽。
6. 测试检查行为与约束，不重复实现；小文案修改只做对应检查。
7. 不记录凭据或个人机器路径；脚本提供明确失败退出码。
8. 新增实验编排、数据处理、验证和绘图优先使用 Julia；现有文献工具/原生钩子允许有边界保留。
   算法自实现应限定适用范围，并通过解析例、穷举和成熟工具对照；技术路线见 [Julia 设计](julia-design.md)。

完整回归默认执行 `scripts/test.jl`。CI按 `r1_r4`、`r5_r6`、`r7_r9` 三组并行，
每组仍使用隔离的 `Pkg.test` 环境与十分钟步骤上限；分组不能省略已有测试。
这不改变各科学求解的预算和验收阈值，文档发布须等待全部组及项目检查通过。

## 文档展示

- 函数说明以 Julia 中文 docstring 为准；Documenter `@index` / `@docs` 提供索引和原生 API 卡片。
- 模型说明直接链接 API，源码/测试仅登记位置与验证名称；不将完整实现抄入文档。短小调用示例可用 doctest。
- 模型关键方程使用居中的独立数学块，右侧保留原论文式号；项目补充与推导单独编号并说明来源。
- 公式与符号读取权威记录，避免正文和清单漂移。宽屏正文使用侧栏之外的可用宽度，长公式在局部滚动。

## 研究证据

- 公式、数据和目标图表记录物理页码、印刷页码及式表号。
- 明确单位、时间尺度、变量范围、初始/终端条件、近似和求解器假设。
- 区分原件、转换件、估读与自行设定；关键符号回原页核对。
- 实验前确定指标、容差、算力预算和停止条件；变更须有新决策记录。
- 每次运行记录提交、工作区状态、环境、配置和输入哈希、种子、命令、状态及耗时。
- 检查物理平衡、约束残差、成本分项；松弛结果回代原模型。
- 局部可行解、上下界、最优性证明分别陈述，无证据不写全局结论。
- 保留不一致、不可行、超时、数值失败、未核查和负结果，并说明判定依据。

论文复现的逐阶段门槛、统计与图表验收以 [复现验收协议](reproduction-acceptance.md)为准。
该协议的阈值须在正式实验前冻结；它不会把工具预检通过改记成科学阶段完成。

## 完成标准

工程任务：行为和说明一致，相关检查通过，差异可审查，下一步入口明确。
研究任务还须达到预先规定的研究接受条件并有证据。
证据不足时报告边界和所缺材料，不宣布复现成功。
