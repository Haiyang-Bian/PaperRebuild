# 从固定价格走向策略报价：先核清支付

第5章原文PDF85说明IES能够通过报价影响市场出清，PDF86将不能影响价格的情形作为退化情况。
已有[共同承诺](ch05-commitment.md)、[风险调度](ch05-risk.md)及[条件分解](ch05-benders.md)
回答的是“给定价格后，应该承诺多少购电与备用”。本页记录连续策略报价连接前的支付代数和独立验算。
后续单IES乐观解释的实现见[连续报价与风险连接](ch05-strategic-model.md)；
本页历史支付核查不改判为策略实验。

## 1. 三个不同的数

- **出清目标：**发电与备用报价成本，减去IES购电报价对应的效用。它决定市场选哪些报价。
- **IES净支付：**实际出清价格乘成交量，购电支出减去备用收入。
- **IES运行费用：**净支付再加设备运行、实时补救等费用；还需指定风险模型。

出清目标为负不等于IES获利，备用中标也不等于所有情景下都能交付。
原(5-6)中的价格乘成交量在策略报价时是双线性项。
本批通过下层市场的驻点、互补和守恒，将全部IES的全时域净支付写成可核查的线性表达。
项目编号、逐符号定义与原式参照由[支付推导台账](ch05-strategic-equations.md)生成。

## 2. 先从最简单的移项检查

采用市场目标等于“发电侧三类报价成本＋IES备用报价成本－IES购电报价效用”。
所以将IES报价部分移到左侧时，必须同时减去发电侧的能量、上备用和下备用报价成本。
PDF90原(5-59)在括号里把发电备用项写为负号，与(5-34)不一致。

一小时手算输入的出清目标为−1280，发电能量、上备用、下备用报价成本分别为1600、100、20美元：

~~~math
-1280-(1600+100+20)=-3000,\qquad
-1280-(1600-100-20)=-2760 .
~~~

IES报价部分的原值为−3000，印刷移项相差240美元。
这确证了两条印刷公式之间的代数冲突，不证明作者实际程序也使用了这个符号。
原式不删除；采用版R5-SP2从已经独立验证的出清目标重新移项。

## 3. 为什么能消掉价格乘成交量

按[出清对偶约定](ch05-market.md)，能量乘子π及备用乘子σ已经包含时间步。
节点价格还要减去PTDF与线路拥塞乘子的贡献，再除以时间步。
因此直接支付既可以用“价格×MW×h”算，也可以用“含时间步的乘子×MW”算，不能再重复乘h。

推导分为四步：

1. 将发电能量、上下备用的驻点关系分别乘以对应成交量并求和；非负变量的约化费用项由互补关系消失。
2. 用发电物理容量、报价容量和爬坡互补，把“乘子×变量”替换为“乘子×外生边界”。
3. 用节点能量、备用守恒，从发电侧收入中分离普通负荷支付、系统备用需求支付和全部IES净支付。
4. 用线路互补处理拥塞项。爬坡项在全时域相邻抵消，但留下首时段乘子差乘初始出力。

对应R5-SP3各分项为：

| 分项 | 计算含义及代码键 |
|---|---|
| 发电报价成本 | dt乘能量及两种备用报价成本：generator_energy/up/down |
| 物理容量项 | 上容量乘子乘Pmax，减下容量乘子乘Pmin：generator_capacity |
| 报价容量项 | 能量与两种备用报价上界乘子分别乘容量：generator_bid_capacity |
| 爬坡容量项 | dt乘上下爬坡乘子及MW/h速率：ramp_capacity |
| 初始出力项 | 首时段上下爬坡乘子差乘已知初始出力：ramp_initial |
| 线路项 | 上下线路乘子之和乘线路容量：line_capacity |
| 普通负荷支付 | 含dt的节点乘子乘普通负荷，取负：ordinary_load_payment |
| 系统备用支付 | 含dt的备用乘子乘系统需求，取负：system_reserve_payment |

廉价机组初始30 MW、首时段最多增加20 MW、负荷100 MW的测试中，
初始出力项为900美元；漏掉它会破坏恒等式。
报价上界不同于物理容量上界，两组乘子不能合并漏计。

这个表达在其他发电商报价、容量及系统输入外生时是线性的。
它只适用于**全部IES合计、全时域求和**；存在多家策略主体时不能直接拿它代替某一家的支付，
也不能把相邻时段抵消后的总式误作逐时恒等式。

## 4. API与数学检查

[`r5_market_payment_identity`](@ref)只读取已保存的出清量和原始/转换乘子，
返回直接支付、线性式分项、逐IES账目、残差和适用标志，不求解或修改历史记录。
通过条件同时要求市场原约束、原始对偶KKT和支付恒等式成立。
仅数值上两种支付相等，不能代替乘子可信性。

~~~julia
saved = read_r5_market_run("results/runs/r5/r5-market-depot-20260919/hand_hour--highs")
payment = r5_market_payment_identity(saved.case, saved.result)
payment["valid_for_reformulation"]
~~~

69项专项测试包含：一小时与四分之一小时、线路拥塞、报价容量、非零初始爬坡、
多IES合计、无IES退化、缺失候选、转换乘子和原始乘子篡改。
手算净支付为600美元，四分之一小时为150美元；出清目标仍是另一个数。

## 6. 下一步如何接入策略报价

以下为支付核查节点确定的实施顺序，后续实际完成情况见[策略模型](ch05-strategic-model.md)：

1. 显式定义原(5-32)连续报价边界、可报价容量和外生竞争者；先从单个IES开始。
2. 连接出清原约束、对偶可行、驻点及互补，独立重解下层核查；避免任意大M或隐式价格截断。
3. 声明多最优解的选择规则。上层能选择有利成交量与价格属于乐观双层解释，需另作价格范围和退化测试。
4. 将共同成交量连接到既有多情景补救和风险模型；支付恒等式通过不代替实际备用交付检查。
5. 比较价格接受者与策略报价者，再冻结样本外统计方案。小系统机制与论文规模收益分别报告。

当前完成的是策略报价所需的代数基础和原值复核。尚未完成连续双层优化、策略收益、
样本外可靠性或全文数值复现；整体进度见[全文完成清单](reproduction-coverage.md)。
