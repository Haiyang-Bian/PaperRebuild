## 2. 本项目选择怎样的可比构造？

保持现有44电节点、38热节点、24小时合成输入，从8个AG派生16和32个AG。
它使用已有第7章替代系统检验第4章F13的问题，**不是作者6/15/30主体算例的同输入复现**。

对每个父主体，在原电/热节点创建`k`个子主体。运营商、背景负荷、线路、管道、价格、
时间步、全部原设备容量及状态不变。原设备整台归第一子主体，其他子主体可以仅有负荷。
同一储能的全部充放电决策仍属于原设备，不能拆成若干可独立充放的小电池。
`k=1`原字节保留；其他版本的父子身份单独登记。

每个载体分别使用

```math
d_{ir,t}^{\rm ref}=\frac{d_{i,t}^{\rm ref}}{k},\qquad
\bar d_{ir,t}=\frac{\bar d_{i,t}}{k},\qquad
a_{ir}=k a_i.
\tag{R9-SC1}
```

灵活比例和功率因数不变。若不调整`a`，同一总负荷变化的最小不满意度将缩为原来的`1/k`，
那样改变的是经济问题，不能归因为“主体变多”。
继承的来源元数据仍描述父输入；子主体是项目派生身份，不能当作作者的新参数。

## 3. 为什么集中最优资源费用保持不变？

先从任意父调度构造子调度。所有设备、网络和开关控制原样保留，负荷和上图量等分：

```math
d_{ir,t}=d_{i,t}/k,\qquad w_{ir,t}=w_{i,t}/k;
\qquad d_{i,t}=\sum_r d_{ir,t},\quad w_{i,t}=\sum_r w_{ir,t}.
\tag{R9-SC2}
```

等分保持负荷边界与不满意度锥；节点净电注入、无功、热源和热需求的总量相同。
热端口流量按**热节点**编号，既不拆分也不按主体重复。网络可行性及设备模式保持，
目标上图量总和不变。这给出“父可行→子可行且费用相同”。

反过来，将任意子调度的负荷和上图量相加，设备与网络控制不变。令
``\delta_{ir,t}=\bar d_{i,t}/k-d_{ir,t}``，``\bar\delta_{i,t}=\sum_r\delta_{ir,t}/k``，则

```math
J_k-J_1
=\Delta t\sum_{i,t} k a_i\sum_{r=1}^{k}
  (\delta_{ir,t}-\bar\delta_{i,t})^2\ge0.
\tag{R9-SC3}
```

电、热各计一次。该恒等式是平方展开；设备和外购费用相消。由此聚合上图量仍覆盖父主体
二次费用，得到“子可行→父可行且实际资源费用不增”。两向构造合起来证明集中最优值相同。
证明对相同固定离散方案和同一完整整数域均适用，也不要求电网锥必须取等。
实际数值是否通过采用模型及原等式A1，仍需分别回代。

**手算例：**`k=2`、`a=40 CNY/(h MW²)`、`Δt=1 h`，两个子主体的偏差围绕平均值为
`+0.125/-0.125 MW`，额外费用为`2×40×(0.125²+0.125²)=2.5 CNY`。
所以任意子候选的实际费用并非必然等于聚合费用；只有集中最优值等价。
测试同时保留这个正差反例，避免把“最优值等价”误写成“所有调度费用不变”。

## 4. 等价性不覆盖什么？

- 独立自调度、零售上限、P2P结算、议价权和个体收益随主体身份改变。本构造不比较AG0或参与收益率。
- 通信盒按新归属重新计算。主体数、消息维度、负荷分布及数值尺度共同改变；不把时间差解释为纯硬件并行加速。
- 采用现有串行ADMM模拟。连续固定模式与混合整数启发式分别对照；不宣称与作者嵌套ATC–ADMM等价。
- 当前子块建模仍分配全局设备/主体数组，并把不活跃分量固定。时间包含这种实现结构的开销，不能只用理论迭代次数解释。
- 稳态热能量/质量包络仍不能认证温度混合、完整水力或动态输运。
- 现有规模子块精度问题可能仍阻断迭代。结果须保留，不能把缺失的完整轮数画成收敛。

## 6. 正式12方法与完整预算

协议为`configs/r9/scalability-study.toml`。按8、16、32个主体依次运行，每组为
固定模式集中、固定模式ADMM、整数集中、整数ADMM。每个集中/分布配对使用同一输入和离散域，
固定模式沿用准备包；不从集中候选初始化分布方法。消息和缩放乘子仍从零开始，`ρ=1`，
外层上限1000轮。连续版使用Clarabel，整数版使用Gurobi；精度与前一走廊批次逐字段核对。

每方法启动独立Julia 1.12.6进程，单线程、串行执行。启动器记录的完整墙钟是主要时间指标，
包括进程启动、加载、JIT、建模、求解、独立核验和原始结果保存。前420秒是外层截止，
预留180秒核验和封存；600秒到期时仅终止该方法的子进程句柄，保留部分文件和日志。
实际终止耗时原样报告，轮询/终止开销导致的超时不会被截成600秒或标为预算通过。
集中入口原有内部核验预留仍保留，不宣称集中和分布使用了完全相同的净求解秒数。

本分配在新正式结果产生前确定。旧8主体运行发生完整流程超预算，且同一约106 MB轨迹写了三次；
新流程采用共享冻结源码，每方法只写一份完整原始轨迹。ADMM末次验证和时间字段另存，
只允许补充`validation`、`elapsed_sec`及`budget_overrun`，不得替换迭代、控制量、状态或候选。
重读时重建完整结果并调用冻结验证器。节省归档开销是工程改动，不是新的优化算法；
与旧协议的耗时不作因果加速比较。

正式目录由使用者给定，已有目录/方法拒绝覆盖：

```sh

```

VS Code提供对应测试、冻结、整批执行和单方法重验任务。冻结清单包含准备包原清单的哈希、
三套输入、父子映射、固定模式、科学源码、执行脚本和环境。各方法保留独立启动/终止收据；
进程退出0只说明记录写出，不表示算法成功。进程被终止而缺失完整轨迹时，轮数记为未知，
不能按零轮处理，也不从日志猜测可行性。

比较时分别报告协调A4、合并模型A1、原电网关系、可行资源费用、有效界、目标报告一致性和完整耗时。
最后一次未通过A1的低费用不进入可实施费用排名；增广子块界不能相加为系统界。
一个方向的边界标量数仍为`4×主体数×24`。这是逻辑消息维度，不是实测网络通信或并行时间。
本批没有真实网络部署，不把这种串行模拟宣传为隐私/通信性能测试。
