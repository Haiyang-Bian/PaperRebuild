# 有限支持风险调度：费用、舒适与履约

本页实现`r5_finite_support_checked_v1`：共同日前承诺、有限支持最坏费用和联合室温风险的直接模型。
价格仍外生，补救知道完整情景轨迹。原文依据为PDF92–94，物理模型沿用[确定性补救](ch05-dispatch.md)。

## 1. 为什么需要两种“最坏分布”

日前购电和备用容量只能选一次。备用调用、光伏等未来轨迹改变实时费用；历史频率也未必准确。
有限支持集合允许在冻结情景之间移动概率质量，移动总距离不超过半径。
费用对手把概率向昂贵情景移动；舒适风险对手把概率向越界情景移动。两者通常不同。

只有名义权重变动，情景轨迹本身不改变。没有出现的极端天气或调用不会由这个集合自动产生。
本批距离是三种完整调用类别的独热编码欧氏距离除以√2，半径是合成实验设置；不能解释为数据校准的置信保证。
理论背景见[Esfahani与Kuhn的作者预印本](https://arxiv.org/abs/1505.05116)，本项目不直接继承其连续支持或统计结论。

## 2. 联合事件覆盖整条轨迹

采用原(5-70)/(5-80)一致的定义：**至少一个楼宇、一个时段的室温越界，即该情景联合事件失败**。
原(5-75)的冲突保留在[概率审计](ch05-probability-audit.md)。所有原式对应关系、项目编号和符号见
[风险方程台账](ch05-risk-equations.md)。

每情景一个二元开关，值为0时要求全部舒适约束成立；值为1时只允许退到显式物理温度域。
开关为1也可能恰好舒适，故另算实际事件。建筑初末状态、管道水温、设备容量、网络和备用交付始终是硬约束。

~~~math
L_j\le T_{jti}\le U_j,\qquad
\underline T_j-(\underline T_j-L_j)z_i\le T_{jti}
\le\overline T_j+(U_j-\overline T_j)z_i.
\tag{R5-R-demo}
~~~

例如舒适区间是293.15 K单点、物理域为292.15–294.15 K，则上下两项大M恰为1 K。
它是由边界推出的最小有效值；不需要任取巨大系数。物理域本身是项目新增假设，必须评估其作用。
设备或购电容量不足，即使允许所有情景室温越界，也不能靠这个开关消除。

## 3. 最坏费用为何能变为线性约束

固定补救策略后，寻找最坏概率是有非空有界可行集的运输LP。
它的对偶使用非负的预算乘子和自由的概率守恒乘子。将对偶约束与全部情景调度同时建模，
得到含舒适开关的MILP；固定全部开关后是LP。费用可为负，不能给对偶自由变量额外加非负界。
原/对偶写法参考[JuMP官方说明](https://jump.dev/JuMP.jl/stable/tutorials/conic/dualization/)，实现没有增加Dualization依赖。

名义概率严格为正，但最坏概率可能为零。直接模型可能没有把零权重情景的费用逐一压到最低，
因此本批不从联合乘子中提取条件梯度。最坏策略费用、全模型有效界及每个条件费用最优性是不同证据。

交付误差的线性上图也可能不取等。保存原值，独立成本使用真实绝对交付误差，另存上图费用。
由于罚价非负、误差约束为上界，减小该辅助量不会破坏物理关系；模型上界与实际策略费用分别报告。

## 4. 一个能手算的舒适风险对照

在原单时段合成案例基础上，另建0.1小时无损延迟、负荷回温有界和建筑末温free的新输入。
源温330.15 K、初始室温293.15 K，舒适目标仍为293.15 K。
冷却或升温1 K改变建筑热量0.0142 MWh，传输历史使当期电锅炉电量改变0.01278 MWh。

名义未调用/上调用/下调用概率为0.5/0.25/0.25。
若允许下调用情景升温1 K，则当期总耗电上界由0.142增至0.15478 MW。
可取共同承诺(P,U,D)=(0.08,0.08,0.07478) MW，期望净费用为1.0626美元；
全部舒适时为2.085美元。这是手算基准，不是论文真实市场收益。

距离为1时，单个名义概率0.25的违约情景，在半径0.05下最坏概率为0.30。
因此ε=0.25会禁止上述放松，ε=0.30才允许。费用也必须换成其各自最坏分布重新计算，不能只改风险标签。

新手算例的末温是free，原固定末温案例仍保留；不得把不同终端条件的费用作公平周期收益排名。
四时段输入沿用原建筑末温initial、管温free；仍不构成完整周期热状态恢复。

## 5. Julia运行与独立验收

API为原生docstring卡片：[`R5RiskCase`](@ref)、[`build_r5_risk`](@ref)、[`solve_r5_risk`](@ref)。
直接MILP用HiGHS或本机Gurobi；Clarabel穷举3情景全部8种舒适模式，每种仅解LP。
全枚举必须包含所有模式的可行界或不可行证据，缺少分支不得声称全局最优。

~~~julia
using PaperRebuild, JuMP, HiGHS
c = load_r5_risk_case("configs/r5/risk/thermal_e030_r005.toml")
r = solve_r5_risk(c; optimizer=HiGHS.Optimizer, budget_sec=60)
r["validation"]["risk_pass"]
~~~

正式入口预先固定求解器容差与29项规则；建模、分支及三个运输证书共用每方法60秒。
发生超时而未完成证书时保留候选与未验收状态，不偷偷延长预算。

~~~powershell
julia +1.12.6 --startup-file=no --project=. scripts/test_r5_risk.jl
julia +1.12.6 --startup-file=no --project=. scripts/check_r5_risk.jl
julia +1.12.6 --startup-file=no --project=. scripts/study_r5_risk.jl r5-risk-new
~~~

[`validate_r5_risk`](@ref)不重新优化；从原值重算物理、交付、成本、联合事件及运输证书。
原始微小越界与超过温度A1门槛的事件分别报告。概率质量和风险余量仍按1e-8检查。
保存和重读使用[`save_r5_risk_run`](@ref)、[`read_r5_risk_run`](@ref)，拒绝覆盖和篡改。
