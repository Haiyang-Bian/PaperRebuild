## 固定分支为何必要

每个情景的舒适开关同时控制其全部楼宇/时段。固定它后，补救是连续线性问题。
branch=0保持舒适带；branch=1允许室温在已声明的物理域内变化，设备、供能、交付和末期硬关系仍保留。
只有同一固定分支的对偶能形成该分支的费用下界。

本节点每个情景独立求解。即使费用最坏分布给某情景零权重，也不跳过它，更不把联合乘子除以零。
对偶方向依照[MOI约定](https://jump.dev/MathOptInterface.jl/stable/background/duality/)；
分解结构参考[JuMP官方教程](https://jump.dev/JuMP.jl/stable/tutorials/algorithms/benders_decomposition/)。
这两个来源不替代论文特有的物理、风险和舒适开关推导。

## 收入为何影响割的有效性

补救费用含实时收入，可能为负。例如本节点的合成数学测试将实时价固定为600 USD/MWh，
上调用的补救成本为−29.54 USD。它与固定日前费用不同，也不是负资源消耗。

若停用另一个分支的割时留下费用不小于零，就会错误排除这个合法负费用。
[`r5_benders_bounds`](@ref)先根据设备、交付、误差和输运边界推导完整有限盒，再计算可为负的费用下界。
[`r5_benders_cut`](@ref)据此计算停用常数。主问题从原始子问题记录重新计算割，不直接信任外部传入的系数。

## 不可补救诊断不是供能成功

没有找到解、求解器证明不可行和诊断目标为正分别记录。
诊断放松等式及不等式关系，变量仍留在输入推导的物理盒内；每项松弛用冻结的全盒行尺度归一化。
因此诊断可以说明承诺与关系冲突，却不能把加入松弛的点当成实际调度。

原(5-96)在舒适开关为零时仍保持硬舒适。本项目选择了明确的phase-I诊断，
将舒适关系也作为弹性行；这是需要后续评价排序影响的算法选择，不冒称原式等价改写。

测试中的0.9 MW购电承诺超过负荷与电锅炉的吸收能力，成本子问题不可行，诊断可产生有排除作用的割。
零购电则可由本地GT供能，并非同一个反例；早期错误测试预期已记录并修正，没有调整模型或验收阈值。

## 数值证书怎样核验

先从原始数值和乘子独立检查原始可行性、对偶方向、互补、驻点和原对偶差。
成本子问题再经过既有热输运、建筑、网络和实际费用回放；诊断只检查其声明的弹性模型。
KKT沿用1e-6，费用原对偶差沿用A2的1e-4，物理A1不放宽。

通过KKT后，用全盒界扣除微小驻点/符号误差能造成的下界误差；原始乘子始终保留。
旧`float_box`的保护比例为1e-10，定义见R5-BD4；这不是严格有理数或区间算术证明。
新`rational_box`将已编码的二进制浮点数精确转为有理数计算保护量，再向安全方向转换回浮点系数。
它证明的是有限盒内该条割的下界性质，不是输入物理常数精确、MILP精确求解或整篇论文正确。
诊断割在来源点没有正下界时记为无排除作用，不将其计为算法进展。

## 主问题怎样获得上下界

[`build_r5_benders_master`](@ref)同时选择日前承诺、舒适开关和情景费用上图。
费用与风险分别用一套有限支持运输对偶，区别于原(5-85)只固定一次最坏权重的写法。
子问题只接收当前主问题的承诺和分支，不接受直接参考解作为初值或方向。

每轮顺序为：主问题 → 全部情景成本LP → 对明确不可行情景诊断 → 加割或加入关键情景 →
全策略费用/风险回查。全情景补救和三份运输见证通过后，才能更新可行上界。
主问题的有效求解器界与可行策略费用分开，界不从情景最优值或参考解拼接。

| 路线 | 不可行处理 | 可报告的界 |
|---|---|---|
| `cuts` | 条件弹性可行性割 | 完整风险策略域 |
| `critical` | 插入关键情景完整可行性关系，其他舒适开关保持自由 | 完整风险策略域 |
| `paper_critical` | 另执行原(5-102)：关键集外的舒适开关固定为零 | 当前受限域；关键集覆盖全部情景后才是完整域 |

关键集扩张时，旧受限域的下界不能用于扩大后域的全局下界。
手算测试中，三条路线恰巧都得到2.085 USD；受限路线仍记录`restricted_domain_gap`，
不将相同费用误当作同域最优性证明。关键情景辅助调度也不代替最终全部情景的独立重算。

默认外层使用有理割算术及1024倍诊断数值表示；显式传入旧默认`R5BendersSpec()`仍使用旧保护和原表示。
全部嵌套阶段共享最多600秒，默认200轮。费用完成、数值停止、原模型可行及受限域停止分别保存。

## 边界反例：为什么诊断接近零还会停滞

同一手算输入中，下调用需满足 ``P^{DA}+R^d\le0.142`` MW。
开发阶段出现两层独立的数值问题，旧运行和科学源码均保留：

| 表示 | 观察 | 外层结果 |
|---|---|---|
| 浮点保护、原表示 | 保护量约2.69×10⁻⁷，使主问题落在可行边界外约5.40×10⁻⁷ MW | 第3轮无有效排除割，保留旧候选9.46 USD |
| 有理保护、原表示 | 边界缝隙缩至约1.30×10⁻⁹ MW；约−3.3×10⁻¹⁰的负弹性量抵消正电平衡违反 | 仍停滞；不能据近零诊断宣布调度可行 |
| 有理保护、等价表示 | 预先声明 ``u=1024y`` 后，负弹性量消失，割截距恢复至约−0.071 | 第3轮取得2.085 USD并通过既定间隙检查 |

这里的有理运算没有修改原始乘子；等价表示分别保存求解器原始变量/乘子及其单位还原量。
关系是 ``\lambda=1024\lambda_{solver}``，不是任意调整乘子使KKT通过。
HiGHS的原始可行性容差作用于其数值模型，可参考[官方数值选项](https://ergo-code.github.io/HiGHS/dev/options/definitions/)。
缩放没有放宽A1、A2或KKT，也没有把失败的旧运行改成成功。

这只解释已观察到的反例；不保证任意规模的纯割算法不再停滞。
热风险例开发测试得到1.36648 USD，零最坏权重例5.5 USD，四分之一小时例0.52125 USD，
均与另行求解的直接模型一致。尚不能从这些小例推断论文规模的速度优势。
四时段`future_e030_r005`的完整域关键情景路线19轮取得35.66961485078 USD，
与另行直接求解的同模型费用通过A2；该开发验证保留显式历史、建筑状态和风险分支，后续正式批次见本页开头链接。

## Julia调用与VS Code入口

在仓库根目录运行下列脚本，VS Code分别提供Benders tests和Benders mapping任务：

~~~powershell
julia +1.12.6 --startup-file=no --project=. scripts/test_r5_benders.jl
julia +1.12.6 --startup-file=no --project=. scripts/test_r5_benders_loop.jl
julia +1.12.6 --startup-file=no --project=. scripts/check_r5_benders.jl
julia +1.12.6 --startup-file=no --project=. scripts/r5_benders.jl run configs/r5/risk/hard_zero.toml results/runs/r5/benders-new cuts
julia +1.12.6 --startup-file=no --project=. scripts/r5_benders.jl verify results/runs/r5/benders-new
julia +1.12.6 --startup-file=no --project=. scripts/r5_benders.jl compare results/runs/r5/benders-new results/runs/r5/r5-risk-20260919/hard_zero--highs
~~~

下面展示接口用法。构造函数不求解、不写文件；求解和诊断须显式调用。

~~~julia
using PaperRebuild, HiGHS
c = load_r5_risk_case("configs/r5/risk/hard_zero.toml")
x = Dict("P_DA_MW" => [0.08], "R_up_MW" => [0.08], "R_down_MW" => [0.062])
r = solve_r5_benders_subproblem(c, 2, x; optimizer=HiGHS.Optimizer)
check = validate_r5_benders_subproblem(c, r)
cut = check["kkt_pass"] ? r5_benders_cut(c, r) : nothing
~~~

补救目标为USD，诊断目标无量纲，二者不与日前总费用混用。
每次调用建模、求解与核查计入预算；嵌套时deadline只能缩短可用时间，不能重新取得完整预算。
没有可信对偶时保留候选和失败原因，不生成可信割。

外层入口为[`solve_r5_benders`](@ref)，存档和重读分别使用[`save_r5_benders_run`](@ref)、
[`read_r5_benders_run`](@ref)；完整文件清单、源码快照和每轮证据均校验哈希。
存档的`code/replay.jl`使用冻结科学源码重验，不重新求解。
[`compare_r5_benders_runs`](@ref)仅比较同输入保存结果，受限域候选费用差不作为完整域最优间隙。
VS Code提供outer tests、run、verify saved、compare saved任务；运行需新目录，不能覆盖历史。
