# [R3 首批可行性闭环：运行教程](@id ch03-r3)

本批回答：**近似模型给出的流量，能否在详细热网中完成调度？若不能，哪里冲突，改变流量后能否恢复？**
输入全部为合成数据。作者投影梯度、四种运行模式和论文规模对比不属于本批。
理论和项目编号方程见[采用解释](@ref ch03-r3-theory)，原算法见[原式台账](@ref ch03-algorithm-equations)。

## 1. 先手算物理边界

热负荷0.15 MW、回水313 K、供水最高363 K、比热4200 J/(kg K)。

```math
\dot m_{min}=\frac{10^6\times0.15}{4200(363-313)}
=0.7142857\ \mathrm{kg/s}.
\tag{R3-E1}
```

所以0.5 kg/s虽满足管道流量盒，仍不可能在该温度边界供出0.15 MW。
这只是必要条件：历史水团、损耗以及四时段不同负荷会进一步限制可行性。
在`configs/r2/single-source.toml`中保持原设备、网络、历史和负荷不变，将初值显式设为0.5即可检验恢复流程。
修改初始化流量不改写案例，原输入和新增流量计划分别计算哈希。

## 2. 为什么先固定流量

固定每根管每时段的流量后，累计质量决定α/β、停留时间及损耗系数。
热功率和混合变为温度的线性关系，剩余电/水锥松弛构成连续SOCP；实际约束类型随构建结果保存。
`flow_schedule[p,t]`的单位是kg/s，数组第一维为管道、第二维为时段；禁止零/负流量和不满足端口质量守恒的计划。
历史不足直接报错，不用零温度补齐，也不把非整步延迟四舍五入。

以下是调用示例。所有API的参数、单位和限制来自[原生docstring卡片](@ref api-reference)。

```julia
using PaperRebuild, Clarabel
c = load_r2_case("configs/r2/single-source.toml")
b = build_r3_subproblem(c, ones(1, 4))  # 只构建，不求解和写文件
r = solve_r3_feasibility(c; initial_flow=ones(1, 4),
    convex_optimizer=Clarabel.Optimizer)  # 此可行例无需商业修正
dir = save_r3_run(c, r)
checked = read_r3_run(dir)
checked.validation.physical_pass
```

## 3. 冲突诊断与修正顺序

1. 读取明确流量或同输入的已保存SCHPD结果；缺省先求SCHPD。初始化失败会保存失败原因，不换默认流量。
2. 固定流量求详细WMM调度。通过后尝试有证明的κ重构，保留原始解和重构解。
3. 若只剩电网原等式失败，保持流量求含原等式的详细调度。
4. 仍未获得可接受调度，则独立求弹性热诊断。其数值只解释热功率/混合/输运/损耗冲突，不是可执行解。
5. 直接修正流量，最小化归一化绝对改动，再固定已通过物理检查的流量优化费用。

这一步直接修正是**项目补充基准**，不是论文的对偶/投影更新。
初值、SP、诊断各至多60秒，修正至多300秒，末次调度使用600秒共享截止时间的余额。
缺许可、预算用尽、数值失败、已证明不可行分别记录；求解器未找到解不自动写成“无解”。

## 4. 直接运行与VS Code任务

从仓库根目录执行。完整非凸闭环使用已配置的`tools/solvers`环境；许可文件不进入项目。

```sh
julia +1.12.6 --startup-file=no --project=. scripts/test_r3.jl
julia +1.12.6 --startup-file=no --project=. scripts/experiment_r3.jl single-fixed --open
julia +1.12.6 --startup-file=no --project=tools/solvers scripts/experiment_r3.jl
```

批次输出打印`R3_STUDY=.../study.toml`。其中每个条目的`directory`指向独立运行目录。
下面用实际路径替换`RUN_DIR`和`STUDY_TOML`，不自动选择可能不相关的最近运行。

```sh
julia +1.12.6 --startup-file=no --project=. scripts/r3_task.jl validate RUN_DIR
julia +1.12.6 --startup-file=no --project=. scripts/r3_task.jl stages RUN_DIR
julia +1.12.6 --startup-file=no --project=docs scripts/r3_task.jl plot RUN_DIR
julia +1.12.6 --startup-file=no --project=docs scripts/report_r3.jl STUDY_TOML
```

验证命令在无物理可行候选时返回非零，已设计的容量反例也如此；阶段比较仍可查看其诊断。
绘图读取保存结果，不重新求解；每次重绘使用新目录。报告重新计算验收，不直接信任保存的绿色标志。
VS Code的“运行任务”提供同名R3入口，验证/比较/重绘会提示填写运行目录，报告提示批次清单。

## 5. 如何读证据

| 文件/字段 | 解释 |
| --- | --- |
| `case.toml` | 完整案例，包括历史和单位；合成来源明确 |
| `run.toml` | 全部阶段和最终候选索引；原始解不被重构或后续阶段覆盖 |
| `metadata.toml` | 输入、原始数值、代码/环境快照的哈希和Git位置 |
| `stages.csv` | 停止状态、求解目标、费用、距离、耗时和A1分别列出 |
| `residuals.csv` | 每个公式/节点或管道/时段的残差、原单位、阈值 |
| `solver_objective` | 当前阶段真正优化的量；查`objective_kind`后解释 |
| `operating_cost` | 从设备和购电数值独立计算的费用；诊断解费用不可执行 |
| `solver_bound` | 只属于`bound_objective_kind`，不能跨目标或阶段使用 |
| `figures*/` | F04/F05、逐点CSV、绘图配置及文件哈希 |

F04的比值大于1表示未通过A1；无数值解不能画残差，不等于残差为零。
F05温度虚线为独立累计质量回放，实线为该阶段温度；阶段跳变不是梯度收敛。
各温度面板自动选择纵轴范围，跨面板比较时须同时读取刻度；精确数值在图源CSV中。
最终须同时回答四件事：初始固定流量是否可行、是否找到修正流量、最终调度是否物理可行、费用优化是否完成。

本批执行结果见[六案例报告](@ref ch03-r3-results)，开放/商业求解器相同SOCP的A2核验见[参考对照](@ref ch03-r3-reference)。
