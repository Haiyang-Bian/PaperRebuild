# R6：统一日模型与六种不确定性方法

本节点把已冻结日轨迹连接到连续报价、市场出清和内部电热调度。
六方法构建/训练入口已实现；正式验证选参、1000日测试与F17–F19尚未完成。
来源及编号方程见[方法台账](r6-method-equations.md)，统计规则见[数据教程](r6-data.md)。

## 同一座系统，改变什么？

先固定同一套设备和市场。面对明天的光伏与备用调用，各方法采用不同的费用与风险规则：

| 方法 | 训练日/费用规则 | 室温要求 |
|---|---|---|
| D 确定性 | 全部训练PV均值、零调用的单个名义日 | 名义日全部楼宇时段满足舒适界 |
| SP 随机优化 | 100代表日按训练簇概率计算期望 | 全部代表日满足舒适界 |
| RO 鲁棒优化 | 100代表日中的最坏费用 | 全部代表日满足舒适界 |
| DRO 分布鲁棒 | 冻结距离运输球中的最坏期望费用 | 全部代表日满足舒适界 |
| CCP 机会约束 | 训练经验期望费用 | 整日联合违约概率不超过0.05 |
| DRJCC 分布鲁棒联合机会约束 | 运输球最坏期望费用 | 同一概率集合中最坏整日违约概率不超过0.05 |

机会约束只放松室温舒适界到共同物理温度域；设备、网络、成交交付和末期条件仍是硬约束。
费用最坏分布与风险最坏分布分别计算，不能用一个替代另一个。
每天一个放松开关不代表实际发生越界，最终事件由保存温度的独立回放判断。

原文PDF100称D忽略实时调用，PDF101又称采用平均情景。本项目采用表中明确解释，
仍计算名义日的内部费用；不将这一补全写成作者唯一实现。
SP使用训练经验概率，不知道合成分布的真实最优策略。RO/DRO的保证限于冻结支持，
支持之外的新轨迹需要另行实测。

## 24小时物理边界

`configs/r6/physical-rule.toml`先声明曲线，再由Julia生成独立`daily-small.toml`。
每一项t代表从0点开始的区间[t−1,t)，所有方法共享：

- 两电节点、两热节点、一个建筑，EB/GT/CHP/PV和同一充足供给外部市场。
- 父四小时案例的设备容量、爬坡、建筑热容、导热、热管参数和原始温度历史。
- 新的显式24小时气温、负荷与价格曲线；没有把四小时随机轨迹重复六遍。
- 建筑20摄氏度初值、19–21摄氏度舒适界，18–22摄氏度物理域；计算全部用K。
- 建筑末温等于初温，管温终端显式为free。因此不能把日费用称为严格循环恢复费用。

继承的第5章电网为线性电压幅值模型，热网为固定流量输运；本节点不认证交流损耗或水压。
第二阶段已知完整未来轨迹，是两阶段调度，不能称因果在线控制。

例如某小时光伏比例0.5、PV额定0.08MW，则可用量为0.04MW；调用比例−0.3表示
下调调用比例0.3、上调为0。可用光伏不等于必须发电，备用成交也不等于实际交付。

## 从一条轨迹到一个训练模型

[`r6_dispatch_day`](@ref)执行比例/方向转换；[`r6_training_case`](@ref)仅接受完整train分组，
重新核对冻结聚类的身份与概率，然后创建共享日前变量和逐日补救。
市场仍有连续价格报价、下层KKT与显式乐观选择；没有为了开发方便换成外生固定价格。
[`build_r6_model`](@ref)只建模，[`solve_r6_training`](@ref)调用已有共享预算和独立验证闭环。
硬舒适四方法固定z为零，不增加无用二进制量。

RO采用最大支持点距离作为运输半径。对任何概率q都能构造运输矩阵
``\Pi_{ij}=q_i p_j``，其总距离不超过最大距离，所以该集合恰好覆盖有限支持上的全部概率。
由此最坏期望等于最大情景费用；推导见R6-M3。它没有覆盖任意连续光伏/调用轨迹。

## 开发测量与正式统计分开

`pilot-rule.toml`预先固定六方法、最先三个训练代表、条件簇概率、rho=0.01和每项120秒。
它仅测量24小时建模/求解成本并核查保存重读；D仍使用全部2000训练日均值。
另构建100代表SP模型记录实际规模，不在该开发批次优化1000个测试日。
三个代表可能每个概率都超过5%，此时机会约束自然无法放松任何一个，不能据此评价风险方法收益。
rho=0.01不是验证选出的参数。正式半径候选与选取规则须先冻结，再用500验证日选择。

~~~powershell
julia +1.12.6 --startup-file=no --project=. scripts/test_r6_methods.jl
julia +1.12.6 --startup-file=no --project=. scripts/check_r6.jl
julia +1.12.6 --startup-file=no --project=. scripts/pilot_r6_training.jl results/runs/r6-training-pilot-v1
~~~

求解前脚本要求科学源码和规则已提交，已有目标目录拒绝覆盖。原始策略结果按方法分存，
模型通过、风险通过、费用完成与未完成状态独立记录。API见[原生卡片](r6-api.md)。
